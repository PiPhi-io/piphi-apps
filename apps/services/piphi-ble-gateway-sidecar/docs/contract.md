# Runtime Contract

Generated by `piphi-network-create`.

- Integration ID: `piphi-ble-gateway-sidecar`
- Kind: `sidecar`
- Preset: `sidecar-worker`
- Domain: `sidecar-service`
- Port: `4210`
- Deployment mode: `sidecar` (shared singleton)
- Compatible parent: `piphi-network-passive-ble-monitor >=0.4.0,<0.5.0`

`GET /health` is the sole public route. Every other Runtime SDK endpoint uses
Core internal authentication. `/v1/ble/*` uses a distinct 16–256 character
consumer bearer token and opaque consumer ID. A registration must contain a
bounded matcher; optional BTHome bind keys must be scoped to matched opaque
handles and remain memory-only.

On Linux, Bleak owns scanning over BlueZ while a narrow D-Bus adapter reads
Adapter1 properties and can set `Powered=true` only for the selected adapter.
The deployment mounts the system bus and rfkill data read-only plus one
owner-only persistent directory for the opaque-handle key and replay checkpoint.
No BLE device entities are created by this transport service.

## Automation Command Payload

`POST /command` accepts the Core automation runtime contract:

```json
{
  "contract_version": "automation.runtime.command.v1",
  "command": "refresh",
  "target": {
    "config_id": "demo-device",
    "device_id": "demo-device",
    "entity_id": null
  },
  "params": {},
  "capability": "device.refresh",
  "capability_requirements": ["device.refresh"]
}
```

Return `{"ok": true, ...}` for accepted commands. For validation failures, return `{"ok": false, "error": "unsupported_capability", "message": "..."}` with an appropriate 4xx status.
