# MQTT broker 0.2.0 audit remediation

This release closes the immediately actionable single-trust-domain gaps found
in the 0.1.7 Home Assistant quality comparison:

- default-deny ACL restricts the configured principal to `MQTT_TOPIC_PREFIX/#`;
- TLS and optional client-certificate authentication are supported;
- plaintext transport requires an explicit private-network opt-in;
- credentials can be read from a mounted secret without process arguments;
- packet, payload, connection, queue, memory, and durable-session limits are set;
- malformed directives and paths fail closed;
- generated password, ACL, and broker config files are installed atomically;
- Docker health performs an authenticated MQTT 5 round trip;
- container tests cover auth rejection, ACL denial, MQTT 5, QoS 1, retained
  persistence, TLS, secret hashing, and health.

The service remains deliberately scoped to one trust domain. Per-workload
principals, online rotation/revocation, HA/failover, automated encrypted backup,
disk-pressure telemetry, and destructive failure testing remain future work and
must not be implied by the registry listing.
