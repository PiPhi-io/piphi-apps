# MQTT broker 0.4.0 lifecycle hardening evidence

Version 0.4.0 adds software-only lifecycle and release controls without changing
the package's platform-service kind or claiming physical/deployment
qualification.

- Broker-enforced username-derived client IDs provide stable, bounded session
  identity; policy and secret input sizes fail closed.
- Identity reload commits only after authenticated readiness; explicit revoke
  plus forced disconnect requires every remaining client to reauthenticate.
- Inflight count/bytes, offline queues, retained cleanup, stale sessions, policy
  cardinality, heap, payload, packet, keepalive, and persistence free space are
  bounded.
- Curated `$SYS` metrics and readiness/storage age are available only to the
  health principal through a payload- and identity-free diagnostics document.
- Startup, interrupted identity transaction, restart restoration, coupled-state
  restore, read-only root filesystem, mTLS, revocation, MQTT 3.1.1/5, QoS 1/2,
  retained clear/replay, stale readiness, and disk flush are covered by synthetic
  Mosquitto/client tests.
- Node base image, npm lockfile, Mosquitto, OpenSSL, and `su-exec` inputs are
  pinned. Release policy blocks high/critical production dependency and exact
  image findings.
- The reusable exact-image script requires an immutable digest, source revision,
  version, and explicit amd64 or arm64 platform.

Release publication, exact-digest verification, and registry synchronization
remain separate gates. The registry must preserve its existing publication,
rollout, lifecycle, Bronze quality tier, and unverified qualification state.
Disk-full injection, corrupt-database repair, host backup systems, load/soak,
orchestrator behavior, and physical/field deployment remain unqualified.
