# MQTT broker 0.3.1 production-hardening evidence

Date: 2026-11-17

## Rebaseline

The 0.1.7 audit was rechecked against the current 0.3.0 package before changes.
Releases 0.2.0 and 0.3.0 had already implemented authentication, prefix ACLs,
managed multi-principal policy, credential reload/revocation, TLS, bounded broker
resources, authenticated MQTT 5 health, safe config tokens, retained-data restore,
and container protocol tests. Those controls were retained rather than duplicated.

The remaining high-impact software findings were:

- managed ACL filters were confined to the global PiPhi prefix but not to one
  declared workload namespace;
- the mTLS probe reused the server certificate and private key as a client
  identity;
- secret path validation accepted lookalike prefixes;
- startup did not require an authenticated protocol round trip before promoting
  the candidate configuration;
- credential generation could replace one candidate file before all generated
  identity state was ready;
- certificate rotation had no package-owned validation/restart helper;
- connection logs could contain client identifiers and usernames;
- numeric resource overrides lacked upper bounds.

## Implemented contract

- Every managed principal now has one explicit workload namespace. For 0.3.0
  compatibility, an omitted namespace is accepted only when all filters infer the
  same safe first segment. Duplicate/cross-namespace policies fail closed.
- Reserved broker/control trees have explicit deny ACLs and broker system-topic
  publication is disabled.
- Server TLS material is staged with Mosquitto-only permissions. mTLS requires a
  distinct health-client certificate/key. Rotation validates key matching and the
  health-client trust chain, records a payload-free audit event, then forces all
  sessions to reauthenticate through restart.
- Startup and readiness perform an authenticated MQTT 5 subscribe/publish round
  trip and persistence write probe. Liveness performs an authenticated MQTT 5
  connection. Probe failures emit no sensitive protocol context.
- Password and ACL candidates are both generated before installation. A malformed
  replacement policy leaves the active identity files usable.
- Connection, packet, payload, inflight, queue count/bytes, memory, keepalive, and
  stale durable-session bounds are rendered with validated upper limits.
- Configuration output no longer reports policy digests or topic prefixes, and
  connection records that include workload identifiers are disabled.

## Version decision

`apps/piphi.service.mqtt-broker/v0.3.0` was the newest matching local tag and
GitHub release. No matching 0.3.1 tag or release existed at the check time, so
0.3.1 is the next unused immutable patch. No tag, release, image, pull request,
or external registry entry was created by this work.

`sha256:b3d5051383ccd0e227e168a0187975f79170fd48b1bc46dd43c591deb81e1073`.
It contained Mosquitto 2.0.22, Node 20.20.2, and OpenSSL 3.5.9. The protocol suite

published multi-architecture manifest remain unverified.

## Residual risks and excluded claims

- The managed manifest keeps explicit plaintext-on-private-service-network and
  legacy single-principal modes for compatibility. Neither is a multi-workload or
  cross-host security boundary; production shared deployments must use managed
  policy plus TLS/mTLS as appropriate.
- Alpine package repositories are not snapshot-pinned, so a future rebuild can
  resolve a different Mosquitto/OpenSSL patch despite the pinned base image.
- The development dependency tree has one low-severity `esbuild` Windows
  development-server file-read advisory. The production dependency audit is
  clean, the image excludes development dependencies, and no development server
  is shipped or run.
- Mosquitto 2.0.22 does not support the newer per-client subscription-count
  directive; no subscription-count limit is claimed.
- Active-active operation, automatic failover, online selective client eviction,
  encrypted backup orchestration, disk-full/corrupt-database recovery, load/soak
  envelopes, and published-image provenance remain unverified.
- Physical-device and field qualification are outside scope and were not
  performed or claimed.
