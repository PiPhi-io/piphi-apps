# MQTT broker 0.3.0 lifecycle and recovery remediation

This release addresses the shared-infrastructure gaps intentionally left in
0.2.0:

- a versioned policy defines distinct workload principals with separate mounted
  password secrets;
- each principal has explicit read and write filters confined beneath the
  configured PiPhi prefix;
- duplicate users, broad topics, reserved topics, malformed filters, and a
  missing or duplicate health identity fail closed;
- password and ACL databases are regenerated atomically and reloaded with an
  audit record that contains no topic, payload, or secret;
- revocation can force all existing sessions to disconnect and reauthenticate;
- container qualification proves cross-workload denial, password rotation, old
  password rejection, forced restart, and retained-data restore into a fresh
  broker container.

The broker still does not claim active-active replication, automatic failover,
online per-client kick without restart, encrypted backup orchestration,
disk-full/corruption recovery, or a published performance envelope.
