## What upstream automates without hardware

- The Home Assistant repository does **not** currently exercise AP discovery, `/get_db`, pagination, authentication, WebSocket reconnects, or tag transfers in its test suite. Its `tests/` tree contains drawing/rendering tests; the shared fixtures mock Home Assistant, serial, Bluetooth, tag metadata, and fonts, while tests compare generated images with checked-in PNGs ([fixture](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/tests/drawcustom/conftest.py#L1-L16), [mock tag/display](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/tests/drawcustom/conftest.py#L54-L66), [representative golden-image assertion](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/tests/drawcustom/rectangle_test.py#L12-L36)). There are no AP-response fixture files in that tree. Thus the API cases below are contracts inferred from first-party client and firmware source, not cases proven by upstream tests.
- CI runs `pytest tests -v` with Python 3.12 on `ubuntu-latest`; HACS validation, hassfest, and release jobs also use `ubuntu-latest` ([test workflow](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/.github/workflows/tests.yml#L10-L36), [HACS](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/.github/workflows/HACS.yml#L7-L15), [hassfest](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/.github/workflows/hassfest.yml#L10-L15), [release](https://github.com/OpenEPaperLink/Home_Assistant_Integration/blob/f28c21761365181cfaf203030678f1c29433baf3/.github/workflows/release.yml#L11-L20)). There is no OS, architecture, Python-version, AP-model, or firmware-version matrix.

## Source-derived `/get_db` contract and representative variants

The firmware always creates a top-level `tags` array. It emits live records until the serialized response exceeds roughly 5,000 bytes, then adds `"continu": c + 1`; `?pos=N` resumes from that database position. `?mac=...` selects at most one record. An invalid MAC still receives HTTP 200 with `{"error":"malformatted parameter"}` ([serialization/paging](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/tag_db.cpp#L141-L166), [HTTP handler](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/web.cpp#L338-L356)). Representative shapes are therefore:

```json
{"tags":[]}
{"tags":[{"mac":"0011223344556677","hash":"…","lastseen":0,"nextupdate":0,"nextcheckin":0,"pending":0,"alias":"","contentMode":0,"LQI":0,"RSSI":0,"temperature":0,"batteryMv":0,"hwType":0,"wakeupReason":0,"capabilities":0,"modecfgjson":"","isexternal":false,"apip":"0.0.0.0","rotate":0,"lut":0,"invert":0,"updatecount":0,"updatelast":0,"ch":0,"ver":0,"imgtype":0}]}
{"tags":[{"mac":"0011223344556677"}],"continu":17}
{"error":"malformatted parameter"}
```

The complete emitted field list is defined by `fillNode` ([fields](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/tag_db.cpp#L169-L202)). The core repository's AP tool follows `continu` until it is absent and documents that one `curl` does not retrieve every page ([tool implementation](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/miscellaneous/ap-tool/aptool.py#L48-L61), [tool documentation](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/miscellaneous/ap-tool/README.md#L24-L45)). The firmware cursor is stored as an 8-bit `startPos`, so source review alone does not qualify databases beyond that range ([cursor type](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/web.cpp#L348-L354)).

### Identifiers and pending semantics

- Firmware output uses an uppercase, unseparated 16-hex-digit identifier. Input accepts either 12 or 16 hex digits and reverses textual byte order into the internal array ([MAC conversion](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/tag_db.cpp#L120-L138)). Consumers should preserve the full returned `mac`, not truncate it or assume colon-separated Ethernet form.
- `pending` is an integer queue count (`pendingCount`), not a Boolean. Queueing increments it; cancellation and successful transfer reconcile it with the remaining queue; timeout clears/dequeues items; loading the persisted database resets it to zero ([emission](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/tag_db.cpp#L178-L188), [queue/cancel](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/newproto.cpp#L137-L188), [completion/timeout](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/newproto.cpp#L611-L683), [reload reset](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/tag_db.cpp#L264-L287)). It means queued work known to the AP, not guaranteed RF delivery or display refresh.

## Discovery, access, and failure assumptions

- No HA test or fixture establishes automatic AP discovery. Firmware normally builds `OpenEpaperLink-` plus the final two interface-MAC bytes as its hostname unless an alias replaces it; the core AP tool instead requires an explicit `--ap HOST[:PORT]` or `OEPL_AP` value ([firmware hostname](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/wifimanager.cpp#L399-L419), [tool address contract](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/miscellaneous/ap-tool/README.md#L9-L22)). Treat discovery as an unverified convenience, not the sole setup path.
- The firmware `/get_db` route performs no authentication check, and the core reference tool constructs plain `http://HOST` requests without credentials ([firmware route](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/web.cpp#L338-L356), [tool client](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/miscellaneous/ap-tool/aptool.py#L31-L46)). The optional WPA2 password protects the fallback configuration WLAN, not this HTTP route ([fallback AP](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/ESP32_AP-Flasher/src/wifimanager.cpp#L377-L395)).
- No HA test covers initial refusal, timeout, malformed JSON, disconnect, AP reboot, backoff, state retention, or reconnect. The core manual tool's distinct reboot helper sleeps three seconds, then polls `/sysinfo` every two seconds for up to 120 seconds ([manual helper](https://github.com/OpenEPaperLink/OpenEPaperLink/blob/96bfd389b71451a289a172dd4298876f04709fb2/miscellaneous/ap-tool/aptool.py#L63-L72)); that is useful operational precedent but is not evidence of the HA integration's reconnect behavior.

## Qualification limit

This evidence can justify parser mocks and software compatibility tests, but it cannot replace physical qualification for any AP board/radio, tag model, display controller/color plane, power source, RF environment, or AP/tag firmware combination. In particular, mocked/golden-image tests and source inspection do not demonstrate DHCP behavior on a real network, radio association and wake/check-in timing, queue-to-air transfer and retry behavior, correct pixels on a panel, battery effects, reboot recovery, or compatibility with model-specific capabilities. A support claim should therefore name the physically tested models and firmware versions separately; “matches `/get_db` source” is not hardware qualification.
