# KNX 0.2.4 release evidence

Version `0.2.4` adds continuously evaluated datapoint freshness, deduplicated
`datapoint.stale` and `datapoint.recovered` transitions, stale and numeric-range
automation conditions, and degraded session diagnostics. Fresh feedback is the
only recovery signal; reads do not manufacture freshness.

Release acceptance retains the `0.2.3` immutable-image requirements and adds:

- deterministic stale, repeated-observation, and recovery tests;
- behavior/catalog/manifest synchronization for every new state, event, and condition;
- no host, group address, or value topology in diagnostics or stale events;
- healthy exact-digest execution as UID/GID `10001` under the hardened runtime profile.

Additional DPTs, ETS import, secure KNX modes, physical interfaces, firmware,
electrical paths, and field datapoints remain unverified.
