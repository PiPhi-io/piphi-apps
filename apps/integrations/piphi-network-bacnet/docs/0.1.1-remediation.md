# BACnet 0.1.1 remediation evidence

Version 0.1.1 closes the highest-risk software findings from the portfolio
Home Assistant quality review without broadening the deliberately narrow,
read-only Kaiterra profile.

## Behavior changes

- `/health` is the sole public endpoint. Every operational route requires a
  constant-time checked Core-issued runtime token and fails closed when runtime
  authentication is not configured.
- Setup and reconfiguration perform a bounded Who-Is/profile/snapshot probe
  before replacing active configuration. Failed replacement leaves the prior
  config, poller, and state intact. Changing the active BACnet client interface
  requires explicit removal first rather than destructive implicit replacement.
- Poll failures preserve the last good metrics with `connected=false` and
  `stale=true`, record last success/failure, exponentially back off with bounded
  jitter, and emit one unavailable transition. Recovery clears stale state and
  emits one recovered transition.
- The image build now consumes the checked-in lock with hashes, pins its base
  image by digest, runs as fixed non-root UID/GID 10001, and declares read-only,
  cap-drop, and no-new-privileges runtime controls.

## Automated evidence

`tests/test_runtime_hardening.py` covers route enumeration, missing/wrong/correct
runtime tokens, transactional replacement failure, interface-change rejection,
last-good stale state, transition deduplication, recovery, and capped jittered
backoff. Existing protocol/profile, capability-catalog, contract, and conformance
tests remain part of the package gate.

Simulator and automated image checks are software evidence only. Governance
remains draft, rollout remains 0%, quality remains unrated, and qualification
remains unverified. No physical SenseEdge or field qualification is claimed.
