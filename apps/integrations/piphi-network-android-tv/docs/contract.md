## Automation Command Payload

`POST /command` accepts `refresh` and a conservative `send_key` action after
the target has been paired and configured:

```json
{
  "contract_version": "automation.runtime.command.v1",
  "command": "send_key",
  "target": {
    "config_id": "living-room"
  },
  "params": {"key": "HOME"},
  "capability": "device.send_key",
  "capability_requirements": ["device.send_key"]
}
```

Unknown keys, commands, capabilities, or targets fail closed. Raw protocol
keys, text, long presses, and multi-target key fanout are not accepted.

## Pairing endpoints

- `POST /pairing/start` starts an expiring PIN flow.
- `POST /pairing/{session_id}/finish` consumes the one-time PIN.
- `DELETE /pairing/{session_id}` cancels a pending flow.
- `DELETE /pairing/credentials/{config_id}` explicitly forgets local
  credentials after deconfiguration.

`POST /config` connects and authenticates before saving. It returns
`pairing_required` when credentials do not exist.
