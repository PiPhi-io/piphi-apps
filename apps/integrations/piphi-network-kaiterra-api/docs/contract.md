# Kaiterra Runtime Contract

Originally generated by `piphi-network-create`; now hardened around the documented
read-only Kaiterra API surface. `capability-catalog.json` is the executable scope
inventory.

- Integration ID: `piphi-network-kaiterra-api`
- Kind: `integration`
- Preset: `cloud-polling-api`
- Domain: `cloud-api`
- Port: `8090`

## Required Endpoints

- `GET /health`
- `GET /entities`
- `POST /command`
- `POST /config`
- `GET /ui-config`

## Recommended Endpoints

- `GET /diagnostics`
- `POST /discover`
- `POST /config/sync`
- `POST /deconfigure`
- `GET /state`
- `GET /contract`
- `GET /events`
- `POST /telemetry/example`

## Kaiterra API Mapping

- `GET /devices/{device_udid}` is used for device metadata.
- `GET /devices/{device_udid}/top` is used for latest sensor readings.
- The API key is sent as the `key` query parameter.
- `refresh` updates one configured device.
- `sync_cloud` updates all configured devices when no specific config is supplied.

Keep `manifest.json`, `capability-catalog.json`, `contract.py`, `kaiterra.py`,
behaviors, and route handlers in sync. Only `/health` is public. Device selection is
always an explicit secret UDID; the provider contract has no account/device-list
endpoint and the runtime never chooses a first device.
